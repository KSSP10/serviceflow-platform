# Branching and PR rules

- Use trunk-based development.
- Create short-lived feature branches named `feature/your-feature-name`.
- Fix branches: `fix/brief-description`.
- Chore branches: `chore/brief-description`.
- Require a Pull Request for merging to trunk/main with at least one reviewer.
- CI must pass (lint/build/tests) before merge.
- Use semantic commit messages: `feat|fix|chore(scope): short description`.
